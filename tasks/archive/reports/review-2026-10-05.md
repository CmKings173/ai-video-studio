## Required findings

### 1. [P1] Preserve product context when editing a product

Location: frontend/app/products/[productId]/page.tsx:102.

The edit form always sends context as either { tone: data.tone } or {}. backend/apps/api/app/api/products.py replaces each supplied field using setattr, so context is replaced rather than merged.

Trigger: an existing product has context = { tone: "premium", packaging: "glass", constraints: ["keep logo"] }; an editor changes only its name and saves.

Result: packaging and constraints are deleted. An empty tone deletes the entire context.

Remedy: preserve the existing context keys when changing tone, or omit context if tone did not change. Keep the existing revision precondition. Add coverage for renaming a product that contains extra context keys.

Evidence: evaluated the actual patchProduct payload expression parsed from the frontend source; only the tone key survived. Backend replacement semantics were verified by source inspection.

### 2. [P1] Place the backup helper mount before the Compose service

Location: infra/scripts/backup.ps1:20–22.

The command places the new -v mount after api. Installed Docker Compose reports syntax: run [OPTIONS] SERVICE [COMMAND] [ARGS...].

Result: -v is the container command instead of a Compose option; the MinIO snapshot helper is not executed. A PostgreSQL dump alone does not restore the media store.

Remedy: put both volume options before api, then pass python and the helper arguments. Check native command exit codes before recording backup completion.

Evidence: inspected the PowerShell command and verified syntax using docker compose run --help. No production backup was executed.

### 3. [P1] Update restore paths for the backend/frontend split

Locations: infra/scripts/restore.ps1:7 and :30–31; infra/compose.yaml:5.

restore.ps1 still defaults to compose.yaml in the caller's directory, although the repository now stores it in infra/compose.yaml. Even with an explicit -ComposeFile override, restore invokes /app/infra/scripts/minio_snapshot.py. The backend image builds from ../backend and does not copy that helper.

Result: the documented restore command cannot restore PostgreSQL with its default path; after overriding it, media restore still fails.

Remedy: resolve the default Compose path relative to PSScriptRoot and mount the script directory before the api service, as intended for backup, or deliberately include the helper in the backend image. Verify both PostgreSQL rows and media objects in an isolated restore target.

Evidence: verified that the root compose.yaml and backend/infra/scripts/minio_snapshot.py are absent, and inspected backend/Dockerfile. An actual restore was not executed.

### 4. [P1] Distinguish a changed storyboard from a retry of Generate All

Location: frontend/app/videos/[videoId]/page.tsx:305–308.

Generate All always sends {} and keeps its key until onSuccess. If the server commits a batch but its response is lost, and the editor then edits or adds a scene, the next click sends the same payload and key.

backend/apps/api/app/api/generations.py returns the saved idempotency response before inspecting the current scenes.

Result: the old batch is replayed and the new or edited storyboard receives no new generation, while the frontend handles the response as success.

Remedy: track the logical action with the current video/scene revisions and eligible scene selection; keep the key for retries of the unchanged action and rotate it when that input changes.

Evidence: invoked the actual mutation callback extracted from the source before and after changing video revision and scenes; it emitted identical requests. Backend replay ordering was verified in source.

### 5. [P2] Preserve trusted client identity through the login proxy

Location: frontend/app/api/[...path]/route.ts:39–48.

The proxy forwards neither a client IP nor a trusted client identity. backend/apps/api/app/api/auth.py creates a shared ip:<request.client.host> throttle key. In Compose, requests from all browsers reach FastAPI from the frontend service.

Result: failed logins by one editor apply the IP backoff to every editor, including users who submit valid credentials.

Remedy: propagate client identity from a trusted ingress and configure backend proxy trust explicitly, or redesign throttling for this deployment. Do not trust arbitrary browser-supplied IP headers.

Evidence: executed the actual transpiled proxy with a mock fetch transport; no client IP header was forwarded. Verified the backend throttle key and failure handling. Real multi-client login behavior was not tested.
