All routes use `/api/v1`. Existing cookie authentication applies. Mutating generation routes require `X-CSRF-Token`; generation creation, variation, regeneration and Generate All also require `Idempotency-Key`. No frontend files changed.

| Route / DTO | Exact contract |
| --- | --- |
| `GET /generation-capabilities` -> `GenerationCapabilitiesDTO` | Authenticated editor/admin read. `{available, combinations, disabled}`; empty availability is explicit. Each combination contains `workflow_id`, `mode`, `quality_profile`, `aspect_ratio`, `resolved_width`, `resolved_height`, `steps`, `fps`, `workflow_version`, `workflow_hash`, `required_asset_slots`, actual graph-bounded `max_reference_images/videos/audio`, `max_total_reference_files`, clip/category limits, `reference_video_fps`, `audio_requires_visual_reference`. Scene creation preserves only explicitly supplied config fields. |

## Qualification, resolver and worker interfaces

`workflow_contracts.resolve_canvas(resolution: dict, approved: ApprovedWorkflow, ratio: str) -> tuple[int, int]` is the stable public read-only resolver contract offered to the controller. `resolve_frames(profile: WorkflowProfile, approved: ApprovedWorkflow, seconds: float) -> int` describes the submitted graph. `require_contract(record, approved, quality=None, ratio=None) -> WorkflowProfile` is shared by enablement, seed approval, creation/capabilities and dispatch replay validation through `require_frozen(snapshot, record)`.

Profile JSON requires quality, steps, 24 FPS, sampler/scheduler, explicit Turbo boolean, resolution and duration resolver declarations, exact dependency versions, graph setting bindings, and filename-to-SHA256 weight hashes for all model/encoder/VAE/LoRA loaders. Adapter switches/strength declarations must agree with the graph. `poc_verified is True` plus structured executed evidence is required: graph/slot/profile hashes, timestamp with timezone, prompt correlation, runtime/model/LoRA/custom-node provenance, and measured output. Every advertised mode/profile/ratio case must have matching actual video/audio dimensions/FPS and fit native plus profile limits. Existing unqualified enabled database rows remain unusable; no bypass or production escape flag was added.

Native checks prove patched prompt, seed, steps, sampler/scheduler, canvas, frames, FPS and reference inputs reach the collected output. Real reference Autogrow keys are zero-based dotted `ref_images.ref_image_N`, `ref_videos.ref_video_N`, `ref_audios.ref_audio_N`. Video requires the actual LoadVideo/GetVideoComponents path. Requested assets cannot exceed actual symbolic capacity. Native graphs also cannot retain unrequested default conditioning assets: fixed socket exports require the matching `required_asset_slots` input shape; other input-count variants need independently qualified exports/normalization. No runtime graph rewriting or paired-video-soundtrack normalization was invented.

Selector source SHA256 is pinned to `3fe5c3f9aeceed343725a91c6feaa13377b5ebad2c95fd633e3806d69d10bcc8`. Binary megapixels and nearest multiple-of-32 rounding yield 480x864, 864x480 and 640x640 at 0.4MP. Post-rounding MAX_PIXELS is 768*1344. Duration uses `round(seconds*24)` followed by upward 17k+5 alignment; snapshot `frames` and `resolved_duration_seconds` describe the submitted length, not measured output.

V2 snapshots contain graph/slot/profile versions/hashes, base and patched graphs, requested quality/ratio, resolved canvas/frame/duration, seed policy, ordered frozen assets/checksums, config/source revisions, prompt provenance and semantic hash. `width`/`height` and `scene_revision` aliases remain truthful for old consumers and Phase0 replay. Parent lineage retains the parent semantic hash and explicit overrides. V1 frozen graphs are revalidated without replacement; unknown locks do not invent FIXED policy, and contradictory/unqualified historical parameters are rejected rather than silently rewritten.

Reference validation enforces <=9 images, <=3 videos, <=3 audio, <=12 mixed; each clip 2..15 seconds and each audio/video category <=15 seconds. Audio-only is rejected. Inputs must be distinct, READY with SHA256, correct media kind, project/product scoped, and carry dimensions plus codec and finite stream-span metadata; video must already be normalized to 24 FPS. Missing video/audio stream duration is rejected instead of substituting a longer container duration. Frozen object/checksum changes are rejected before fresh upload/submission; new output metadata never mutates `input_snapshot`.

Durable admission remains exactly one (`lock_scheduler` plus active/uncertain rows, `max_pending_prompts` still constrained to 1). Technical retry is the same generation/new attempt. Uncertain-submit recovery still reconciles correlation without duplicate submission; known rejection remains terminal. Existing auto-selection and generation/assembly ownership behavior remain.
