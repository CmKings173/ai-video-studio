# MiniMax H3 reference repositories versus the AI Advertising Video Studio specification

Research snapshot: 2026-09-10

## Scope and method

This note compares three public GitHub repositories with [`AI_Advertising_Video_Studio_Backend_Technical_Spec.md`](../../AI_Advertising_Video_Studio_Backend_Technical_Spec.md), especially the specification's sections 5-13, 21, 25-28, 31, 33 and 36. The comparison covers MiniMax H3 and ComfyUI integration, generation modes, prompt/reference handling, queue/progress/cancel/retry, the frontend/backend boundary, persistence, runtime assumptions, long-video composition and editor flows.

Only first-party GitHub material was used: each repository's root file tree/README plus relevant raw source, configuration and verification files. Repository counts and visible maturity signals are point-in-time observations, not quality scores. No repository was executed locally and no model weights were downloaded; runtime claims remain claims or documented checks from the repository unless the source code itself establishes them.

Repositories:

- [benjiyaya/Calliope](https://github.com/benjiyaya/Calliope)
- [AntaresAlice/h3-webui](https://github.com/AntaresAlice/h3-webui)
- [TheTerrasque/minimax-h3-frontend](https://github.com/TheTerrasque/minimax-h3-frontend)

## Executive conclusion

The three repositories reinforce the target architecture's most important decision: ComfyUI should remain an AI execution engine reached through an application-owned API, while projects, users, prompt history, generation status and final assets remain application concerns. Calliope is the closest product-flow reference; `minimax-h3-frontend` is the strongest queue/auth/durable-job reference; `h3-webui` is the clearest small H3 protocol and media-preflight reference. None should be adopted wholesale.

The highest-value leverage is to reimplement four patterns inside the existing FastAPI/PostgreSQL/MinIO boundary: (1) a versioned symbolic workflow-slot contract instead of scattered node IDs, (2) immutable snapshots of the exact prompt/render inputs, (3) robust ComfyUI progress/cancel/reconciliation behavior, and (4) H3-specific input validation and benchmark-driven presets. Calliope and `h3-webui` are MIT-licensed; `minimax-h3-frontend` had no root license file or README license grant visible in the inspected tree, so its code and bundled workflow assets should be treated as reference-only unless the owner adds or confirms a license.

## Per-repository findings

### 1. Calliope

#### What it is and where it overlaps

Calliope is a local-first story-to-video application with a FastAPI backend, SvelteKit frontend, SQLite project state, folder-based media, a configurable OpenAI-compatible LLM, external ComfyUI and FFmpeg film export. Its user journey is Story -> Assets -> Script -> Video -> Film, with per-scene rendering, per-entity reference generation, regeneration, previous-clip continuation, and final normalization/crossfade/loudness handling. This is the closest of the three to the target specification's Project/Video/Scene hierarchy and 30/60-second multi-scene assembly flow, though its domain is narrative filmmaking rather than product advertising. [README: architecture, prerequisites and stages](https://github.com/benjiyaya/Calliope/blob/main/README.md#using-the-app)

The root tree shows distinct backend, frontend, example-workflow and changelog areas, and GitHub showed 88 commits at the snapshot date. The repository also exposes a Playground separate from the guided project pipeline and an agent-driven route which writes through the same database and render queue as the ordinary UI. Those are useful signs of a comparatively broad prototype, but do not by themselves establish production readiness. [Repository tree and activity](https://github.com/benjiyaya/Calliope) [README: Playground and Agents](https://github.com/benjiyaya/Calliope/blob/main/README.md#using-the-app)

#### ComfyUI/workflow boundary

Calliope's best reusable design is its symbolic workflow contract. It imports ComfyUI **API Format** JSON, discovers editable inputs/outputs from title tags such as `(Input:prompt)`, `(Input:image)`, `(Input:duration)` and `(Output:video)`, and supports aliases for canonical roles. This directly supports the target spec's Workflow Registry/Router goal while avoiding business services depending on raw Comfy node numbers. Unknown roles remain dynamically editable, which is useful in a technical Playground but should be disabled or allowlisted in the target production editor. [README: role tags and canonical roles](https://github.com/benjiyaya/Calliope/blob/main/README.md#1-tag-your-nodes-in-comfyui) [README: import procedure](https://github.com/benjiyaya/Calliope/blob/main/README.md#4-import-into-calliope)

The ComfyUI transport is cleanly remote-capable: upload through `POST /upload/image`, submit patched JSON through `POST /prompt`, poll `/history/{prompt_id}`, then download outputs; it intentionally does not read ComfyUI's local input/output directories. That is compatible with the target's adapter boundary and is safer than sharing ComfyUI filesystem paths with the API service. [README: HTTP-only integration](https://github.com/benjiyaya/Calliope/blob/main/README.md#6-http-only)

#### Prompts and assets

For H3 reference workflows, Calliope can rewrite a scene into a six-section prompt, assign ordered generic image inputs to scene characters then location, use `<Subject N>` labels, and let explicit form values override auto-filled values. More importantly for an editor product, Generate first opens the exact prompt that will be sent; the user can edit it, regenerate the rewrite, save a draft, cancel without enqueueing, or later inspect each job's prompt/input payload and copy prior settings back to the form. This aligns strongly with the target spec's deterministic base prompt, optional enhancer, prompt snapshots, regeneration and auditability. [README: H3 prompt profile and override rules](https://github.com/benjiyaya/Calliope/blob/main/README.md#prompt-profiles) [README: prompt preview/history](https://github.com/benjiyaya/Calliope/blob/main/README.md#review-the-prompt-before-you-generate)

Calliope's asset flow also demonstrates a useful separation: generate or upload character/location/item references first, then reuse them in scenes; a Playground result may later be attached to a project asset. The target can adapt that pattern for Product/Brand/Project assets, but should retain the spec's immutable MinIO asset records rather than mutable folder paths. [README: Assets stage and Playground](https://github.com/benjiyaya/Calliope/blob/main/README.md#using-the-app)

#### Queue, progress, cancel and retry

The README exposes settings for concurrency, polling interval, timeout and maximum retries, and warns that H3 renders can exceed ten minutes. The source is materially narrower: a single asyncio worker claims one SQLite job at a time, startup resets stale `running` rows to `pending`, and retries are manual; the advertised concurrency and automatic-retry settings are not consumed by the inspected worker/manager. SSE reports lifecycle events, but Comfy render progress in the UI is a synthetic asymptotic estimate capped below completion rather than sampler-step progress. These mismatches make the implementation a useful UX reference but not a queue contract to copy. [README: queue settings](https://github.com/benjiyaya/Calliope/blob/main/README.md#queue-settings) [queue manager](https://github.com/benjiyaya/Calliope/blob/main/calliope-backend/src/calliope/queue/manager.py) [worker](https://github.com/benjiyaya/Calliope/blob/main/calliope-backend/src/calliope/queue/worker.py) [frontend progress store](https://github.com/benjiyaya/Calliope/blob/main/calliope-web/src/lib/jobProgress.ts)

Manual retry resets the same queue row to `pending`. Regeneration supersedes older pending jobs and clears the scene's current clip reference before the replacement succeeds. Cancel marks the job failed with a cancellation error and calls ComfyUI's global `/interrupt`; even a pending application job can therefore interrupt some other Comfy prompt. The target must keep prior successful selections until replacement succeeds, distinguish cancel-requested/cancelled from failure, and address pending/running Comfy prompts separately. [jobs router](https://github.com/benjiyaya/Calliope/blob/main/calliope-backend/src/calliope/routers/jobs.py) [queue manager](https://github.com/benjiyaya/Calliope/blob/main/calliope-backend/src/calliope/queue/manager.py) [video enqueue/regeneration](https://github.com/benjiyaya/Calliope/blob/main/calliope-backend/src/calliope/agent/video_agent.py)

#### What to reuse, and what not to reuse

Reuse by reimplementation: canonical workflow roles and per-version slot maps; exact-prompt preview; saved scene drafts; render-input history; remote-only ComfyUI transport; generate-one/generate-all UX; the idea that human UI and agent tooling must use the same durable services and queue.

Do not copy wholesale: SQLite/folder persistence, mutable path-based media references, LLM-heavy story-agent orchestration, arbitrary user-imported workflows, the queue/cancel implementation, or film-export policy. The API has no authentication in the inspected application, broad CORS, and workflow media inputs can cause the backend to read local paths for upload; it must remain a trusted loopback tool rather than an exposed multi-user service. Imported workflows are executable Comfy graphs with no production allowlist and examples reference hard-coded models, LoRAs and custom nodes. The target requires PostgreSQL, MinIO, RBAC, approved/versioned workflows, confined object-backed inputs, a deterministic composer that works with the enhancer disabled, and immutable final versions. [main.py](https://github.com/benjiyaya/Calliope/blob/main/calliope-backend/src/calliope/main.py) [Comfy client](https://github.com/benjiyaya/Calliope/blob/main/calliope-backend/src/calliope/comfyui/client.py) [example H3 workflow](https://github.com/benjiyaya/Calliope/blob/main/example_ComfyUI_workflows/video_minimax_h3_r2v_2ref_API.json)

Calliope is MIT-licensed and, at the snapshot date, had active releases, a sizeable backend test tree and detailed changelogs. Missing CI workflows, no frontend test script, version-string drift across packages, and the queue/security limitations support an "advanced local creator prototype" maturity assessment rather than hardened production infrastructure. Repository MIT licensing does not replace the MiniMax model license or third-party node licenses. [MIT license](https://github.com/benjiyaya/Calliope/blob/main/LICENSE) [backend tests](https://github.com/benjiyaya/Calliope/tree/main/calliope-backend/tests) [.github tree](https://github.com/benjiyaya/Calliope/tree/main/.github) [backend package metadata](https://github.com/benjiyaya/Calliope/blob/main/calliope-backend/pyproject.toml) [frontend package metadata](https://github.com/benjiyaya/Calliope/blob/main/calliope-web/package.json)

### 2. h3-webui

#### What it is and where it overlaps

`h3-webui` is a deliberately small self-hosted H3 workbench: an `aiohttp` backend, one native-JavaScript HTML frontend, workspace directories containing `generations.json` plus media, and scripts for I2V/R2V/SSE smoke testing. It presents Chat, Overview and Studio views, supports history/parameter reuse, and can continue a video by extracting its last frame. GitHub showed 12 commits and the repository structure is essentially one 1,048-line backend plus one 1,691-line frontend, so it is best treated as a focused integration prototype rather than a backend foundation. [English README](https://github.com/AntaresAlice/h3-webui/blob/main/README.en.md) [Repository tree and activity](https://github.com/AntaresAlice/h3-webui)

#### H3 workflow and runtime specifics

This repository is the most concrete of the three about H3 graph construction. It builds I2V and Ref2VA API graphs directly, pins model/VAE/text-encoder filenames, uses MiniMax H3 conditioning/sampler/decode nodes, and optionally inserts low-VRAM, SageAttention and Turbo LoRA nodes. It validates dimensions as multiples of 32, caps pixel area at `1920*1088`, and maps seconds to H3's `17n+5` frame grid at 24 fps. These rules are valuable PoC hypotheses and regression tests, but the hard-coded graphs, filenames, node types and sampler settings must not become unversioned production constants. [server.py: model/runtime constants](https://github.com/AntaresAlice/h3-webui/blob/main/webui/server.py#L76-L125) [server.py: dimension and duration conversion](https://github.com/AntaresAlice/h3-webui/blob/main/webui/server.py#L166-L215) [server.py: I2V graph](https://github.com/AntaresAlice/h3-webui/blob/main/webui/server.py#L217-L267) [server.py: Ref2VA graph](https://github.com/AntaresAlice/h3-webui/blob/main/webui/server.py#L269-L336)

The implemented UI/API exposes I2V and R2V, not a complete target mode set: T2V and first+last-frame are not first-class generation routes. R2V accepts one to nine images and up to three audio references, validates `<Picture N>`/`<Audio N>` tokens against uploaded counts, validates audio duration, and currently leaves reference-video graph wiring as a future placeholder. That is directly useful for Ref2VA validation design and directly warns against declaring advanced video references complete before a PoC. [server.py: mode routing and I2V preflight](https://github.com/AntaresAlice/h3-webui/blob/main/webui/server.py#L746-L800) [server.py: R2V validation](https://github.com/AntaresAlice/h3-webui/blob/main/webui/server.py#L810-L862) [server.py: reserved video-reference wiring](https://github.com/AntaresAlice/h3-webui/blob/main/webui/server.py#L317-L323)

#### Progress, cancel and persistence

The backend connects to ComfyUI's WebSocket using the same client ID used for submission, maps `progress`, node execution, success, error and interruption into application events, then exposes SSE. The SSE endpoint assigns a monotonic per-process sequence, replays the last or terminal event after reconnect and emits keepalives. This is a strong reference for the target's ComfyUI-event-to-SSE adapter, while the target must durably record state in PostgreSQL and treat SSE as a projection rather than a queue. [server.py: ComfyUI event bridge](https://github.com/AntaresAlice/h3-webui/blob/main/webui/server.py#L337-L396) [server.py: reconnectable SSE](https://github.com/AntaresAlice/h3-webui/blob/main/webui/server.py#L895-L936)

However, active jobs exist only in the process-global `JOBS` dictionary and completed history is JSON on disk. A restart loses in-flight correlation/SSE state; there is no durable dispatch claim, fairness, automatic retry or reconciliation. Cancel calls `/interrupt` and immediately emits an error event, but does not robustly distinguish a pending prompt from the currently executing prompt or resolve a cancel/completion race. [server.py: in-memory jobs and JSON history](https://github.com/AntaresAlice/h3-webui/blob/main/webui/server.py#L126-L165) [server.py: job launch](https://github.com/AntaresAlice/h3-webui/blob/main/webui/server.py#L864-L893) [server.py: interrupt](https://github.com/AntaresAlice/h3-webui/blob/main/webui/server.py#L971-L981)

#### Storage/API/security boundary

Uploads and generated outputs are copied between workspace folders and ComfyUI's input/output directories; image files are decoded and re-encoded, audio/video is probed with PyAV, and path traversal checks exist on media serving. These preprocessing ideas are worth reproducing in a sandboxed media service, but the direct shared-filesystem coupling conflicts with the target's MinIO-as-durable-store and local-NVMe-as-temporary-staging model. [server.py: media upload/probe](https://github.com/AntaresAlice/h3-webui/blob/main/webui/server.py#L595-L660) [server.py: output copy and history record](https://github.com/AntaresAlice/h3-webui/blob/main/webui/server.py#L398-L460) [server.py: media path guard](https://github.com/AntaresAlice/h3-webui/blob/main/webui/server.py#L938-L947)

The route table has no authentication or authorization middleware, and its error middleware can return Python tracebacks to clients on 500 errors. Consequently the server must not be exposed as the target's internal multi-user backend. [server.py: public route table](https://github.com/AntaresAlice/h3-webui/blob/main/webui/server.py#L1015-L1038) [server.py: error response](https://github.com/AntaresAlice/h3-webui/blob/main/webui/server.py#L997-L1013)

#### What to reuse, and what not to reuse

Reuse by reimplementation: H3 geometry/frame preflight, media decoding checks, reference token/count validation, real sampler-step progress, reconnect keepalive behavior, output discovery across ComfyUI history shapes, last-frame extraction, and the included smoke-test scenarios.

Do not reuse as production code: process-global jobs, workspace JSON as source of truth, direct ComfyUI folder access, global client identity, broad traceback responses, unconditional interrupt semantics, hard-coded node graphs/model names, or the single-file frontend. Code is MIT-licensed, but H3 model weights/nodes are separately licensed and not included. [README: license boundary](https://github.com/AntaresAlice/h3-webui/blob/main/README.en.md)

### 3. minimax-h3-frontend

#### What it is and where it overlaps

`minimax-h3-frontend` is a Django/React/PostgreSQL application with Django-Q2, nginx, login/invites/OIDC, per-user job isolation, H3 T2V/I2V/R2V, quality/duration/aspect presets, prompt assistance, queue/history, cancel/requeue and a Director mode for multi-clip video. Its root tree showed backend/docs/frontend/resources plus Docker Compose and 110 commits at the snapshot date. It has the richest application/backend mechanics of the three and is the closest reference for the target's internal multi-user portal, but it deliberately uses a separate application queue and local media volume rather than the target's ComfyUI-owned execution queue plus MinIO. [Repository tree and activity](https://github.com/TheTerrasque/minimax-h3-frontend) [README: feature/stack summary](https://github.com/TheTerrasque/minimax-h3-frontend#features) [Architecture: repository layout](https://github.com/TheTerrasque/minimax-h3-frontend/blob/main/docs/ARCHITECTURE.md#repo-layout)

#### Generation model, prompts and references

`GenerationJob` snapshots mode, raw/improved prompt, preset, megapixels, steps, ratio, width, height, duration and estimated time so later catalog edits do not rewrite history. It separately stores ComfyUI prompt ID, fine-grained phase/progress, cancellation request, output and error. `ReferenceAsset` stores kind/order/file and produces H3-style `Picture N`/`Video N`/`Audio N` labels. This is a strong concrete precedent for the target spec's immutable `scene_generations` input snapshot, prompt snapshot and `generation_id <-> comfy_prompt_id` correlation. [models.py: job snapshots/status](https://github.com/TheTerrasque/minimax-h3-frontend/blob/main/backend/generation/models.py#L158-L255) [models.py: correlation/output fields](https://github.com/TheTerrasque/minimax-h3-frontend/blob/main/backend/generation/models.py#L267-L304) [models.py: ordered references](https://github.com/TheTerrasque/minimax-h3-frontend/blob/main/backend/generation/models.py#L311-L349)

The renderer uses three baked API-format workflows and a pure `build_api_workflow()` patch function. It supports first/last-frame I2V and image/audio/video Ref2VA uploads, but patches known node IDs from constants; the README warns that rewiring those nodes requires updating application code. The target should keep the purity/testability but replace raw node constants with its versioned symbolic slot map. [tasks.py: workflows and node IDs](https://github.com/TheTerrasque/minimax-h3-frontend/blob/main/backend/generation/tasks.py#L20-L79) [tasks.py: reference injection](https://github.com/TheTerrasque/minimax-h3-frontend/blob/main/backend/generation/tasks.py#L209-L240) [README: workflow update caveat](https://github.com/TheTerrasque/minimax-h3-frontend#updating-the-comfyui-workflows)

Prompt refine and chat are optional OpenAI-compatible LLM features. Live chat remains client-side/stateless and is persisted only if its transcript is attached to an actually queued job. The target need not copy chat, but the policy "persist only prompt-building data that produced a generation" is useful for audit/retention, and the raw-vs-enhanced prompt separation matches the spec. [Architecture: prompt integration](https://github.com/TheTerrasque/minimax-h3-frontend/blob/main/docs/ARCHITECTURE.md#llm-integration) [Architecture: prompt chat persistence](https://github.com/TheTerrasque/minimax-h3-frontend/blob/main/docs/ARCHITECTURE.md#L1048-L1064)

#### Queue, progress, cancel, requeue and recovery

The application owns a durable FIFO queue in PostgreSQL and runs exactly one shared Django-Q2 processor. `_claim_next_job()` uses `select_for_update(skip_locked=True)` ordered by creation time, and `process_queue()` recovers orphaned processing jobs before serially draining queued rows. Recovery checks ComfyUI history, then its running/pending queue, and only fails a job when ComfyUI has no record. These mechanics are highly relevant to the target's reconciliation worker, even though the target should not introduce Django-Q2 or duplicate ComfyUI's queue. [tasks.py: queue invariants](https://github.com/TheTerrasque/minimax-h3-frontend/blob/main/backend/generation/tasks.py#L1-L14) [tasks.py: atomic claim](https://github.com/TheTerrasque/minimax-h3-frontend/blob/main/backend/generation/tasks.py#L314-L334) [tasks.py: recovery and processor](https://github.com/TheTerrasque/minimax-h3-frontend/blob/main/backend/generation/tasks.py#L538-L609)

Progress is a best-effort WebSocket side channel with phases `preparing`, `rendering`, `finishing`; success/failure still comes from `/history`. The browser polls the application's job endpoint rather than consuming backend SSE. The target should adopt the separation of progress from truth, but retain its own FastAPI SSE contract and PostgreSQL resync behavior. [comfyui.py: progress semantics](https://github.com/TheTerrasque/minimax-h3-frontend/blob/main/backend/integrations/comfyui.py#L112-L148) [Architecture: frontend polling/progress](https://github.com/TheTerrasque/minimax-h3-frontend/blob/main/docs/ARCHITECTURE.md#L489-L506)

Cancel correctly treats queued and processing states differently: a processing job records `cancel_requested`, tries both `/queue` deletion and `/interrupt`, and lets the worker finalize the terminal state to avoid a cross-process last-write race. The unconditional `/interrupt` is safe only because the repository hardcodes one worker/one in-flight prompt; it is not safe to transplant into a multi-prompt or multi-ComfyUI topology. Requeue creates fresh jobs and copies render snapshots/reference bytes; there is no general automatic technical retry in the main render path. [models.py: cancellation ownership](https://github.com/TheTerrasque/minimax-h3-frontend/blob/main/backend/generation/models.py#L267-L279) [comfyui.py: cancel implementation and single-worker assumption](https://github.com/TheTerrasque/minimax-h3-frontend/blob/main/backend/integrations/comfyui.py#L314-L336) [Architecture: requeue semantics](https://github.com/TheTerrasque/minimax-h3-frontend/blob/main/docs/ARCHITECTURE.md#L509-L535) [tasks.py: failure path](https://github.com/TheTerrasque/minimax-h3-frontend/blob/main/backend/generation/tasks.py#L452-L503)

#### Director/UI/storage/maturity

Director mode layers Projects and ordered Clips over the generation app, with shared prompt/resources, dirty cascades, continuation constraints, per-clip render/cancel and final export. Particularly useful are the rules that a project-wide ratio/quality applies across a continuity chain and that an upstream edit dirties dependent continuation clips. Those map well to target scene selection/reorder/dirty/rebuild behavior. [Architecture: Director model](https://github.com/TheTerrasque/minimax-h3-frontend/blob/main/docs/ARCHITECTURE.md#director-mode) [Architecture: dirty cascade and continuity settings](https://github.com/TheTerrasque/minimax-h3-frontend/blob/main/docs/ARCHITECTURE.md#L631-L666)

The repository has unusually explicit verification documentation and states that login -> queue -> live progress -> download has been exercised against a real ComfyUI instance. It also openly lists gaps: no automated tests, unexecuted full benchmark sweep, direct Django media serving and hand-maintained API/TypeScript types. This supports a maturity rating of "feature-rich validated prototype," not production template. [Function check](https://github.com/TheTerrasque/minimax-h3-frontend/blob/main/docs/FUNCTION_CHECK.md#function-check) [Architecture: deferred work](https://github.com/TheTerrasque/minimax-h3-frontend/blob/main/docs/ARCHITECTURE.md#deferred-to-the-next-pass)

Docker Compose provides PostgreSQL plus separate migrate/backend/qcluster/frontend services and a durable media volume, but not MinIO. Adopting its media model would violate the target's single `ai-video` bucket and presigned upload contract. [docker-compose.yml](https://github.com/TheTerrasque/minimax-h3-frontend/blob/main/docker-compose.yml)

#### What to reuse, and what not to reuse

Reuse by reimplementation: immutable render snapshots; distinct phase/progress fields; cancellation ownership by the active worker; queue/history-based restart reconciliation; input-count validation; queue ETA/presets backed by measured render history; per-user isolation concepts; dirty cascades for continuation scenes; API/function-check scenarios.

Do not reuse as-is: Django-Q2/application-owned FIFO queue, the four-state model where `done` covers both success and failure, direct media `FileField` storage, polling-only frontend progress, single-worker assumptions, raw node-ID patch tables, or experimental image/audio modes implemented by generating a video and extracting a track/frame. The root repository tree and README inspected on 2026-09-10 showed no license file or license grant, so code/workflow copying is not authorized by an open-source license visible in the repository; use ideas only until licensing is clarified. [Repository root tree](https://github.com/TheTerrasque/minimax-h3-frontend) [models.py: success/failure both use `done`](https://github.com/TheTerrasque/minimax-h3-frontend/blob/main/backend/generation/models.py#L158-L172) [README: image/audio workflow reuse](https://github.com/TheTerrasque/minimax-h3-frontend#updating-the-comfyui-workflows)

## Overlap with our technical specification

### Confirmed direction

- **ComfyUI boundary:** all three applications hide the graph editor behind an application API and submit API-format workflows. This supports sections 5-6 and 26: ComfyUI executes graphs; the backend owns business orchestration. [Calliope HTTP boundary](https://github.com/benjiyaya/Calliope/blob/main/README.md#6-http-only) [h3-webui submit path](https://github.com/AntaresAlice/h3-webui/blob/main/webui/server.py#L864-L893) [minimax adapter](https://github.com/TheTerrasque/minimax-h3-frontend/blob/main/backend/integrations/comfyui.py#L59-L110)
- **Scene-oriented long video:** Calliope and Director both build long-form output from ordered clip generations rather than one long H3 call, supporting sections 9 and 27. [Calliope film flow](https://github.com/benjiyaya/Calliope/blob/main/README.md#using-the-app) [Director model](https://github.com/TheTerrasque/minimax-h3-frontend/blob/main/docs/ARCHITECTURE.md#director-mode)
- **Prompt/input provenance:** Calliope's exact-payload preview/history and `minimax-h3-frontend`'s snapshots support section 11.4 and the proposed generation audit fields. [Calliope prompt review](https://github.com/benjiyaya/Calliope/blob/main/README.md#review-the-prompt-before-you-generate) [GenerationJob snapshots](https://github.com/TheTerrasque/minimax-h3-frontend/blob/main/backend/generation/models.py#L204-L228)
- **Realtime is not truth:** `h3-webui` demonstrates Comfy WS -> SSE, while `minimax-h3-frontend` explicitly treats WS progress as best-effort and history/DB as truth. That supports section 21's SSE plus REST/PostgreSQL resync design. [h3 SSE bridge](https://github.com/AntaresAlice/h3-webui/blob/main/webui/server.py#L337-L396) [best-effort progress](https://github.com/TheTerrasque/minimax-h3-frontend/blob/main/backend/integrations/comfyui.py#L120-L143)
- **Runtime must be measured:** H3 pixel/frame constraints, long timeouts, presets and benchmark tooling across the repos support sections 33-34's PoC/benchmark gate instead of promising throughput from nominal aggregate VRAM. [h3 constraints](https://github.com/AntaresAlice/h3-webui/blob/main/webui/server.py#L90-L125) [benchmark warning](https://github.com/TheTerrasque/minimax-h3-frontend#useful-commands) [Calliope timeout guidance](https://github.com/benjiyaya/Calliope/blob/main/README.md#queue-settings)

### Gaps the references do not solve

None of the repositories solves the target's MinIO/DB dual-write lifecycle, one-bucket object-key discipline, immutable final assembly manifest/versioning, ADMIN/EDITOR authorization matrix, fair dispatch across projects/videos, four-GPU topology, or exactly-once behavior at the PostgreSQL -> ComfyUI acknowledgement gap. Their code therefore cannot close the implementation-readiness gaps in the spec without additional design and local fault-injection PoCs.

## Ranked leverage opportunities

### P0 — implement before the first real H3 vertical slice

1. **Versioned symbolic workflow slot schema.** Adapt Calliope's role-tag vocabulary into a stricter registry record: workflow JSON hash, slot-map hash, mode, version, required/optional roles, allowed node classes and output roles. Resolve node IDs once at import/approval; business code injects `PROMPT`, `FIRST_FRAME`, `LAST_FRAME`, `REFERENCE_IMAGES`, `REFERENCE_AUDIO`, `DURATION`, `SEED`, not numbers.
2. **Exact generation snapshot.** Persist raw scene prompt, execution prompt, workflow revision/hash, slot values, reference asset IDs/checksums/order, seed, duration, dimensions, steps and runtime profile before dispatch. `minimax-h3-frontend` proves the practical value of snapshotting mutable presets.
3. **Comfy adapter event/cancel/recovery contract.** Implement submit, queue status, history, output collect, pending delete and running interrupt behind one adapter. Use per-generation client/correlation IDs, durable DB states and terminal-state monotonicity. Borrow `h3-webui`'s WS event mapping and `minimax-h3-frontend`'s history/queue restart checks; do not borrow either one's single-process assumptions.
4. **H3 preflight validator plus PoC matrix.** Encode geometry/frame/reference constraints as an independently tested service, then verify them against the exact approved H3/ComfyUI build. Include T2V, one/two-frame I2V, Ref2VA image/audio/video, output discovery, progress, pending cancel, running cancel and all four GPUs.
5. **Immutable final assembly manifest.** On assemble, snapshot ordered enabled scene IDs, selected generation/output asset IDs/checksums, transitions and audio config. Neither reference repository provides the target's required final-version reproducibility.

### P1 — implement in the product vertical slices

1. **Prompt preview and provenance UI contract.** Return previewed base/enhanced/execution prompt separately; let the editor accept/edit/cancel before enqueue; show past execution payloads and create a new generation for regenerate/variation.
2. **Progress stages plus reliable SSE reconnect.** Store coarse state and latest phase/step in PostgreSQL; emit SSE with event ID/revision/heartbeat; on reconnect refetch REST. Do not rely on an in-memory event queue for recovery.
3. **Cancel-request ownership and reconciliation.** A queued generation can be cancelled synchronously before submit; a running generation records `CANCEL_REQUESTED`, the active worker owns finalization, and late completion cannot regress a terminal state. Reconcile DB state against Comfy history/queue/output after restart.
4. **Dirty cascade and continuity invariants.** If a selected generation, scene order, enabled flag or upstream continuation input changes, mark the video/final state dirty. If continuation is enabled, lock required width/height/duration/settings across the chain as Director mode does.
5. **Benchmark-backed quality presets/ETAs.** Expose editor-friendly draft/standard/high profiles, but store the underlying approved workflow/runtime parameters and snapshot them per generation. Calibrate estimates from local data rather than seeded guesses.
6. **Media preflight and safe staging.** Decode/re-encode images when appropriate, inspect magic bytes and dimensions/duration, validate reference token cardinality, materialize immutable MinIO objects to UUID-named NVMe workspaces, and isolate PyAV/FFmpeg resource usage.

### P2 — useful after V1 is stable

1. A technical Playground for ADMIN/AI-engineer use, backed only by approved workflows and isolated from business records until an output is explicitly attached as an Asset.
2. Previous-clip extension/continuation using real H3 motion/audio context, gated by a separate PoC; last-frame chaining is a weaker fallback and can visibly stutter.
3. Optional prompt chat or role-specific agent orchestration. Keep it outside the mandatory generation path and persist only accepted prompt provenance.
4. Queue ETA, favorites/folders and thumbnail optimizations for a large history.
5. Optional Turbo/Sage/low-VRAM workflow profiles only after creative-regression and stability benchmarks; treat them as separately versioned runtime profiles.

## Risks, compatibility and license notes

- **Model/runtime compatibility:** all repositories assume a particular era of H3 model filenames, ComfyUI nodes and exported graph shapes. These are volatile. Pin ComfyUI commit/container, custom-node versions, model hashes, PyTorch/CUDA/driver and workflow hashes; validate `/object_info` at approval/startup. [h3 model constants](https://github.com/AntaresAlice/h3-webui/blob/main/webui/server.py#L76-L125) [minimax required models](https://github.com/TheTerrasque/minimax-h3-frontend#required-comfyui-models)
- **Node-ID drift:** Calliope's title roles reduce this risk; `h3-webui` and `minimax-h3-frontend` demonstrate how direct IDs/types become application coupling. The target's slot map must be versioned with the workflow, and registry approval must fail if required roles/types are missing. [Calliope roles](https://github.com/benjiyaya/Calliope/blob/main/README.md#1-tag-your-nodes-in-comfyui) [minimax caveat](https://github.com/TheTerrasque/minimax-h3-frontend#updating-the-comfyui-workflows)
- **Queue duplication:** Calliope and `minimax-h3-frontend` add application queues; `h3-webui` submits directly. The target spec intentionally uses ComfyUI's execution queue with only bounded fair dispatch. Reusing Django-Q2 or an in-memory job registry would create the wrong ownership model.
- **Cancel safety:** ComfyUI's `/interrupt` can affect the currently executing prompt, not necessarily a requested ID. It is safe only with a proven one-in-flight topology; pending jobs should be removed through `/queue`. [minimax cancel rationale](https://github.com/TheTerrasque/minimax-h3-frontend/blob/main/backend/integrations/comfyui.py#L314-L336)
- **Storage mismatch:** none of the references has MinIO-backed immutable assets plus PostgreSQL metadata. Their folder/volume cleanup code should not be copied into the target. Design object publish, orphan cleanup, retention and backup as first-class target concerns.
- **Security mismatch:** `h3-webui` is unauthenticated and exposes detailed errors; Calliope is local-first; only `minimax-h3-frontend` meaningfully demonstrates account isolation. Reuse security test cases, not authorization assumptions. [h3 routes/errors](https://github.com/AntaresAlice/h3-webui/blob/main/webui/server.py#L997-L1038) [minimax auth/isolation checks](https://github.com/TheTerrasque/minimax-h3-frontend/blob/main/docs/FUNCTION_CHECK.md#12-auth-gate)
- **Code licenses:** Calliope's repository code is MIT ([LICENSE](https://github.com/benjiyaya/Calliope/blob/main/LICENSE)); `h3-webui` declares its WebUI code MIT and explicitly separates model licensing ([English README](https://github.com/AntaresAlice/h3-webui/blob/main/README.en.md)); `minimax-h3-frontend` had no visible root license/grant in the inspected tree ([root tree](https://github.com/TheTerrasque/minimax-h3-frontend)). Preserve MIT notices for any copied substantial code, and obtain license clarification before copying anything from the third repository.
- **Workflow/model/custom-node assets:** an application code license does not automatically license MiniMax weights, ComfyUI custom nodes, reference media, fonts, screenshots or third-party workflows. Maintain an SBOM/license register and prefer reconstructing approved workflows from official H3/ComfyUI sources.

## Unanswered questions requiring a local PoC

1. Which exact ComfyUI/H3 commit, nodes and model hashes implement T2V, first-frame I2V, first+last and Ref2VA on the target workstation?
2. Does one H3 prompt use one GPU or all four; can multiple pending/running prompts coexist without OOM, thrashing or incorrect `/interrupt` behavior?
3. Are the 32-pixel canvas rule, maximum area and `17n+5` frame grid valid for every approved mode/runtime profile, or only the graphs used by these repositories?
4. What Ref2VA combinations are actually supported: maximum image/audio/video counts, duration/format limits, ordering tokens and whether reference video/audio nodes work end to end?
5. What exact Comfy WebSocket messages and sampler node IDs are emitted in each mode; can trustworthy percentage be shown or only phase/steps?
6. After backend restart, can the target recover by `comfy_prompt_id` from `/history` or `/queue`; how long are those records retained, and what happens after ComfyUI restart?
7. Can a unique generation/attempt correlation value be embedded in client ID, prompt metadata and output prefix so an acknowledgement-gap execution can be found without resubmitting?
8. For pending versus running prompts, which cancellation endpoints are effective, and can a late success/error event arrive after accepted cancellation?
9. How does ComfyUI expose video/audio outputs for each SaveVideo/VHS node and version; can collection be made idempotent by output identity/checksum?
10. Which low-VRAM, Turbo, Sage or multi-GPU settings work on four RTX PRO 5000 Blackwell 48 GB GPUs, and how do they affect product fidelity, motion, audio, latency and stability?
11. Can FFmpeg normalize all produced H3 clips to the selected final resolution/fps/audio layout without visible joins or A/V drift, and what crossfade/continuation policy survives creative evaluation?
12. What is the measured MinIO/NVMe space amplification per mode and duration, and what admission-control watermark prevents generation/assembly failure under concurrent users?

## Recommended disposition

Use all three repositories as test-vector and design references, not dependencies. The immediate engineering spike should create one approved workflow per target mode, a symbolic slot manifest, a fake/real Comfy adapter contract suite, and an end-to-end generation record containing immutable prompt/input/workflow/runtime provenance. Only after that spike should queue concurrency, progress percentage, cancel guarantees and Ref2VA be declared V1-capable.
